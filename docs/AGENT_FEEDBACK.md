# 当前默认：工作过程显示

Codex 接入现在默认显示工作摘要，不再显示百分比。下面的百分比接口说明仅供旧接口兼容参考。

- 提交问题：显示“正在处理本轮问题”。
- 工具开始：显示“正在执行：终端命令 / 文件修改 / 任务计划 / 工具名称”。
- 工具结束：显示“执行结束”，不据此假定执行成功。
- AI 上报阶段：显示简短的公开工作摘要，例如“正在核对结果”“正在整理回答”。
- 等待确认、中断、回答结束：更新为对应状态。
- 最近活动沿用 HUD 的事件记录。没有事件时保留最后状态，不模拟内部思考。

普通提问会自动收到阶段上报规则，无需用户附加提示。脚本支持 `--stage "当前工作摘要"`，不要求百分比。阶段说明仍取决于 Agent 是否执行上报；工具前后事件由钩子自动发送。从本轮钩子提供的会话文件中，仅提取 assistant 的公开 commentary，并按 turn_id 过滤；忽略隐藏推理、最终答案和其他回合。不复制完整终端对话。该文件格式并非稳定接口，Codex 升级后需要验证；文件延迟写入也会使阶段显示延迟。

# Agent 启动与回合进度

双击 `launch_agent.cmd`，或在终端执行 `launch_agent.cmd`。启动器自动检测 PATH 中的 Codex、Claude、Gemini、OpenCode、Aider，再合并 `config/agents.local.json` 的自定义配置。菜单显示名称及程序路径。输入编号，选择工作目录，便会直接启动对应命令行应用，并打开 HUD。不会自动安装 Agent，也不代替各应用的登录。

只查看检测结果：`launch_agent.cmd --list`。直接启动：`launch_agent.cmd --profile codex --hud`。如果程序未加入 PATH，可在本地配置的 `command` 数组中填写绝对路径。这里打开的是 Agent 的命令行应用，不是厂商桌面聊天客户端。

## Codex 自动回合反馈

直接使用 `codex.exe` 时，启动器为本次会话附加生命周期钩子，不修改全局配置。首次启动后，在 Codex 中输入 `/hooks`，审核并信任 UAH 钩子。Windows 使用 `powershell.exe -NoProfile -NonInteractive -EncodedCommand` 启动，内容仅设置 UTF-8、转发钩子输入并调用本插件的 `uah/tools/report_progress.py --hook`。编码避免路径及不同终端的引号解析问题；代码位于 `uah/adapters/feedback.py`。本次 Windows 命令修复改变了定义，旧版已信任的用户也需要重新审核。未信任时 Codex 不执行钩子，HUD 会提示“反馈未连接”。关闭此功能可用 `--feedback off`。

支持这些钩子的 Codex 版本可发送开始、工具结束、等待批准、回答结束和中断事件。回答结束后 HUD 显示“本轮回答已结束”，Agent 进程仍可接受下一个问题，终止按钮仍可关闭整个本次进程。不会读取其他会话的记录。Codex 批处理入口自动退回脚本模式；如需自动钩子，请配置实际 exe 路径。

收到回合开始事件后显示 0%，等待真实的阶段反馈。钩子会要求 Agent 在多步骤任务中维护计划或上报阶段估计。计划显示完成步骤比例；脚本估计标注“AI 估计”。全部步骤已上报但尚未收到结束事件时，最高显示 99%；收到本轮结束事件后显示 100%，表示回答结束，不代表结果通过独立验证。新的问题重新从 0% 开始。

每轮提问都会自动附加反馈规则，普通问答、建议和写作也适用，用户不需要追加“请上报进度”。规则要求在确定回答范围后、主要工作完成后及最终回复前上报实际估计；短回答可在最终回复前上报一次，不强拆虚构步骤。不按时间或工具调用次数虚构进度。模型未执行反馈命令时，中途仍可能保持 0%；反馈未接入则显示明确提示，不假装已经收到反馈。

## 其他 Agent 的脚本反馈

所有通过启动器打开的 Agent 默认继承本次专用 `UAH_REPORT_CHANNEL`。在它启动的进程中调用插件目录里的 `report_progress.cmd`：

```bat
report_progress.cmd --turn-id example-1 --start
report_progress.cmd --turn-id example-1 --percent 35 --stage "正在实现"
report_progress.cmd --turn-id example-1 --completed 1 --total 3 --stage "第一步完成"
report_progress.cmd --turn-id example-1 --done
```

下一个任务使用新的 turn-id。失败用 `--failed`。从其他终端调用时没有本次通道，不能自动关联。脚本不会强迫任何 Agent 自动调用；其他 Agent 需要提示词或其自身的钩子接入。

## 测试方法

1. 启动菜单：双击 `launch_agent.cmd`，确认已安装 Agent 名称与路径；输入编号后确认对应应用启动。
2. Codex 回合：重新启动 `launch_agent.cmd`，完成 `/hooks` 信任；如果信任发生在启动之后，请退出 Codex 再从启动器打开。提问后看 HUD 显示 0%；回答结束看“本轮回答已结束 · 100%”，继续提问应开启新回合。
3. 估计进度：给 Agent 一个多步骤任务，要求它按 UAH 上下文提示上报阶段。HUD 应显示“AI 估计”，不能把它理解成已验证进度。短回答可能没有中间反馈。
4. 终止：在处理问题时、等待输入时、回答结束后分别点击“终止进程”，确认本次 Agent 退出，其他终端不受影响。已经写入的文件不会撤销。
5. 无模型自动测试：执行 `run_uah.cmd uah.tests.verify_progress`。覆盖真实子进程、HTTP 控制、反馈脚本、回合结束后停止、通道隔离以及隐藏窗口组件。它不调用大模型；不能替代第 2、3 步的实际 Agent 测试。

原生钩子行为与信任要求见 [Codex 官方 Hooks 文档](https://learn.chatgpt.com/docs/hooks)。

可直接用来测试的提问：

> 请分三个步骤计算 17+25、计算 12×13、核对两个结果。按照收到的 UAH 反馈说明，每完成一步上报步骤进度；没有 update_plan 工具就使用反馈脚本。最后简短回复结果，不修改项目文件。

预期计划依次上报 0/3、1/3、2/3、3/3；HUD 显示约 0%、33%、66%、99%，本轮结束后 100%。如果执行非常快，界面可能合并刷新而跳过部分中间数值。

### Windows JSON 输入修复

反馈启动命令现在同时指定输入、输出为 UTF-8，读取脚本接受开头的 BOM。旧版本可能在 Windows 默认编码下把 JSON 开头读坏，出现 `JSONDecodeError`；这次编码修复改变了钩子命令，需在 `/hooks` 重新信任。解析失败时 HUD 会明确提示“进度暂不可用”，不会继续把 0% 当作有效进度。没有 `update_plan` 工具也可以通过 `--completed`、`--total` 上报步骤；仅在聊天中写“已完成”不能代替事件上报。
